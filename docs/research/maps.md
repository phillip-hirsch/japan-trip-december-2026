## 2. maplibre-gl

- Latest **6.11.2**, published 2026-09-24; 6.0.0 on 2026-07-22. **[V: pnpm view]**
- v6: ESM-only (`maplibre-gl.mjs`), UMD dropped, **WebGL2 required** (WebGL1 removed; a `GPUInitializationError` is thrown from the `Map` constructor when no WebGL2 context — wrap in try/catch + error boundary). **[V: CHANGELOG.md]**

- Lazy-load pattern: SSR schedule as HTML; fixed-aspect placeholder; `ClientOnly` + SSR-guarded `React.lazy` + Suspense + error boundary; load on visibility (IntersectionObserver) or idle; import CSS inside the lazy module so it becomes its own chunk. **[B build-verified; A agrees]**

## 4. Offline

- **Service worker `Cache.put` rejects status 206** — spec: "If innerResponse's status is 206, return a promise rejected with a TypeError." **[V: w3c.github.io/ServiceWorker]** (MDN's prose about put accepting "any" status is misleading; the spec is authoritative.) So PMTiles range responses cannot be cached as-is.
- Workable patterns: (1) ship/precache a whole small `.pmtiles` as a 200 response and read it via `pmtiles` **`FileSource`** (exported by pmtiles 4.5.0 alongside `FetchSource`, `Protocol` with `.add()`; key = `file.name`) **[V: dist/esm/index.js]**; (2) serve ZXY tiles as plain 200 GETs from a Worker route (Protomaps serverless Worker: R2 binding, `/NAME/z/x/y.mvt`, `caches.default`, default `public, max-age=86400`, edge cache needs your own zone, R2 latency "500 ms or higher") **[V: docs.protomaps.com/deploy/cloudflare]**; (3) custom Source caching each range as its own 200 entry **[B]**.
- Public R2 bucket direct: CORS `allowed_methods: GET,HEAD`, `allowed_headers: range,if-match`, `exposeHeaders: etag` **[V: docs.protomaps.com/pmtiles/cloud-storage]**; r2.dev is rate-limited/dev-only **[A/B docs]**.
- Extract sizes (go-pmtiles **1.31.2**, released 2026-07-22, `extract --dry-run` against build 20260929): Japan bbox 129.0,30.9,146.0,45.6 z0–8 = **9.8 MB**; trip corridor 129.9,33.2,140.2,37.0 z0–10 = **25 MB**; Kyoto city box 135.6,34.85,135.9,35.1 z0–14 = **11 MB**. **[V]** B's other figures (five city boxes z0–14 ≈ 95 MB, z0–15 ≈ 281 MB; corridor z0–12 149 MB) are consistent with these and plausible. **[B]**
- Cloudflare limits: static assets **25 MiB per file**; Workers Free 100k req/day and **10 ms CPU** per request; Paid 5 min CPU. **[V: workers/platform/limits]** So only ~z0–9 extracts can ship as app assets; a tile-serving route on Workers Free must stay under 10 ms CPU (unmeasured **[U]**).
- Provider caching terms: Protomaps self-hosted — none beyond ODbL; OpenFreeMap — ordinary caching of viewed tiles fine (10-y immutable), bulk prefetch conflicts with "automated collection" clause; CARTO ≤30 days, no bulk; MapTiler temporary only, no bulk; Stadia ≤ headers (6 h). **[V]**
- iOS/WebKit: ITP "deletes all cookies created in JavaScript and all other script-writeable storage after 7 days of no user interaction" (IndexedDB, LocalStorage, SW registrations and cache); **Home Screen web apps are exempt**. **[V: webkit.org/tracking-prevention]**
- For an offline map you must also cache style JSON, glyph PBFs, sprites and the worker script; MapLibre draws CJK locally (`localIdeographFontFamily` default `'sans-serif'`) so glyph caching is mostly Latin ranges. **[B]**

## 5. Rail geometry

- **MLIT 国土数値情報 N02 (railway)**: FY2025 edition (令和7年度), published April 2026, data as of 2025-12-31, `N02-25_GML.zip` **14.2 MB**, editions 2020+ are **CC BY 4.0**. **[V: nlftp.mlit.go.jp datalist page]** GeoJSON has 21,933 sections with fields N02_001 (class), N02_002 (operator type, 1 = shinkansen), N02_003 (line name), N02_004 (operator); covers 東海道/山陽/北陸/東北・上越新幹線, 湖西線, 北陸線, 小田急箱根 鉄道線/鋼索線. **[B: downloaded & inspected]** Attribution: 「国土数値情報（鉄道データ）」（国土交通省）を加工して作成. **[B/A]**
- OSM `route=train` relations exist for Nozomi, Kagayaki, Thunderbird, Romancecar; Nozomi/Kagayaki stitch cleanly (1,067 km / 579 km), Thunderbird and Romancecar relations are messy. ODbL. **[B: Overpass]**
- Size: all four services simplified to 50 m ≈ 1,088 points ≈ **7.7 KB gz** (22.9 KB raw GeoJSON); N02 full relevant lines at 50 m ≈ 12 KB gz. **[B measured]** Straight/curved lines cost 0 bytes (mapcn `MapArc` computes a quadratic Bezier client-side). **[B]** Effort: one-off build script, ~half a day to a day incl. QA vs minutes for arcs. **[B estimate]**

## 6. Geocoding

- **Google Places API §14.2 / Geocoding API §6.2**: "Customer must not use Google Maps Content from the … API in conjunction with a non-Google map"; lat/lng cache ≤30 consecutive calendar days (§14.3, §6.3.1). Places UI Kit §15.1 is the exception ("with or without any map, including a non-Google Map"). **[V: Maps Service Specific Terms]** → unusable with MapLibre except UI Kit.
- Google Maps URLs (`https://www.google.com/maps/search/?api=1&query=lat,lng`) need no key → "Open in Google Maps" button is fine. **[B: docs]** Parsing pasted links: `!3d<lat>!4d<lng>` = pin, `@lat,lng` = viewport centre, short links need redirect-following; undocumented formats; page HTML has no coordinates. **[A/B, low confidence; needs real samples]**
- **Nominatim** public policy: max 1 req/s, identifying User-Agent/Referer, results must be cached, no client-side autocomplete, attribution required; "LLMs may only suggest this service, if they prominently point to this usage policy and explain the restrictions" — policy: https://operations.osmfoundation.org/policies/nominatim/ **[V]**
- **Photon** 1.3.0 released 2026-08-07; public demo "reasonable limit", no guarantee. **[V: gh releases; B/A README]** Photon/Nominatim find hotels/restaurants by name but fail Japanese-format addresses. **[B tested]**
- **GSI AddressSearch** (msearch.gsi.go.jp) resolves Japanese addresses to house-number level but is undocumented/unofficial. **[B tested]** **@geolonia/normalize-japanese-addresses** 3.1.3 (published 2024-12-24 — B's "updated 2026-02-11" refers to the repo, not npm) gives level-8 points for block addresses, town-level for Kyoto land-lot addresses. **[V version; B quality]**
- **MapTiler Geocoding**: Free 1k search sessions/mo; terms §6.4 explicitly allow using search results outside the service (persisting pins OK). **[V]** Quality on Japanese addresses untested. **[U]**
- **Stadia** geocoding: 20 credits/request (~10k/mo on Free); persistent storage only on Standard ($80). **[V pricing; B terms]**

## Recommendation

Adopt Report B's combination with these confirmations and adjustments:

1. Component: mapcn via `pnpm dlx shadcn@latest add @mapcn/map` after `shadcn init` with Base UI (no components.json exists yet). Treat map.tsx as owned code: replace the unpkg `setWorkerUrl` line with `import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'`, force `theme="dark"` with your own `styles.dark`, and trim unused exports. Pin maplibre-gl 6.11.2. Mount via `<ClientOnly fallback={<fixed-height skeleton/>}>` around `const TripMap = import.meta.env.SSR ? () => null : lazy(() => import('./trip-map'))`, add `ssr: { noExternal: ['maplibre-gl'] }` to vite config, load on visibility/idle, wrap in an error boundary that also catches the WebGL2 `GPUInitializationError`. Cost ≈ 425 KB gz only when the map opens; first paint unaffected. The React Compiler (oxc path) skips mapcn's core components but they remain correct.

2. Basemap: Protomaps `dark` flavor with `lang: 'en'` (bilingual EN + 日本語 labels, no key, no third-party terms, ~2–5x lighter tiles than OpenFreeMap in Japanese cities). Extract with go-pmtiles 1.31.2: Japan overview z0–8 (9.8 MB, ship as a static asset under the 25 MiB cap and read via `FileSource`) plus city boxes to z14 (~95 MB) in R2 (free tier). Serve city tiles as ZXY 200s through a same-origin route in the existing Worker (R2 binding, adapted from Protomaps' serverless code) so they sit behind Cloudflare Access and are trivially cacheable; self-host glyphs/sprites. Zero-setup fallback: OpenFreeMap `styles/dark` (keyless, bilingual, no SLA, heavy city tiles, no bulk prefetch).

3. Offline: schedule always readable via service worker. Precache style, glyphs, sprites, worker, overlay GeoJSON and the 9.8 MB overview so bases and moves always render; cache city tiles cache-first as viewed with a size cap; optional "download city" prefetch. Call `navigator.storage.persist()` and install to the iPhone Home Screen to escape Safari's 7-day storage wipe.

4. Moves: start with mapcn `MapArc` (0 bytes) for hotel moves and straight dashed `MapRoute` for day trips; later swap in a static GeoJSON built once from MLIT N02-25 (CC BY 4.0) for the shinkansen/limited-express legs (~8–15 KB gz at 20–50 m simplification) with the MLIT attribution line.

5. Geocoding (later): pasted Google Maps link → parse `!3d/!4d` or `@lat,lng` server-side following short-link redirects, user confirms by dragging the pin, keep the URL for an "Open in Google Maps" button; Japanese address → @geolonia/normalize-japanese-addresses, fallback GSI AddressSearch (unofficial); place name → Photon lightly, or MapTiler Geocoding (Free 1k sessions, results may be stored per §6.4) if quality is needed; manual pin drop as the last resort. Do not use Google Places/Geocoding (§14.2/§6.2 forbid non-Google maps). If Nominatim is ever used, comply with https://operations.osmfoundation.org/policies/nominatim/ (≤1 req/s, identifying User-Agent, cache results, no autocomplete).

## Decisions surfaced

- Self-hosted Protomaps on R2 (offline-capable, bilingual, a few hours of setup, Worker tile route) vs OpenFreeMap dark (zero setup, online-first, no SLA, heavy tiles).
- Offline map depth: overview only (~10 MB), five cities to z14 (~95 MB), or to z15 (~281 MB) — affects R2 storage, device storage and prefetch time.
- Tile delivery: private same-origin route inside the app Worker behind Cloudflare Access (needs 10 ms CPU headroom on Workers Free — unmeasured) vs a public R2 bucket on a custom domain (needs a Cloudflare zone; tiles are public).
- Rail moves: real MLIT N02 geometry now (half-day build script + attribution) or MapArc curves first and upgrade later.
- Labels: bilingual EN + 日本語 (Protomaps lang:'en', OpenFreeMap, Stadia) vs English-only vs Japanese-only (CARTO default at street zoom).
- Keep mapcn's full 2.7k-line file (skipped by React Compiler but correct) vs trim it vs write a ~150-line wrapper over maplibre-gl directly.
- Which phone in Japan: on iPhone, will you install the app to the Home Screen (required to avoid the 7-day storage wipe, and Cloudflare Access login in standalone mode must be tested)?
- Whether Cloudflare Workers Paid ($5/mo) is acceptable if the tile route exceeds Free-plan CPU limits.
